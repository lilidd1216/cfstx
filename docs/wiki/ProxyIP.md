# ProxyIP 详解

左侧导航第二项。检测哪些第三方服务器真的能作为反代中继，并区分「真中转」与「直连入口」。

---

## ProxyIP 是什么

### 背景

Cloudflare Workers 提供了一个 `connect()` API，用于从 Worker 内部发起 TCP 连接。但它有一条硬性限制：

> **禁止连接 Cloudflare 自己的 IP 段。**

这意味着：当一个 Worker 需要回源到某个也在 Cloudflare 上的目标时，`connect()` 会直接失败。

### ProxyIP 的角色

ProxyIP 是一台**第三方服务器**，夹在 Worker 和 Cloudflare 之间：

```text
Worker ──connect()──> ProxyIP ──转发──> Cloudflare 边缘 ──> 目标站
```

它本身不在 Cloudflare 网段内，所以 `connect()` 允许连它；它再把流量转发到 Cloudflare。

### 和「优选 IP」的区别（重要）

两者作用在链路的**不同位置**，不能互换：

```text
你的设备 ──①──> CF 边缘节点 ──②──> Worker ──③──> 目标网站
              ↑                    ↑
          优选 IP              ProxyIP
        （客户端入口）        （Worker 回源中转）
```

| | 优选 IP | ProxyIP |
|---|---|---|
| 作用位置 | ① 设备 → CF 边缘 | ② Worker → CF |
| 填在哪 | 客户端订阅的 server 地址 | edgetunnel 的 `PROXYIP` 设置 |
| 出口是谁 | 应该是**你自己**（你就是流量来源） | 应该是**别人**（中转服务器） |
| 判定依据 | 延迟、速度 | 出口 IP ≠ 本机 IP |

**填反了会怎样**：

- 把 ProxyIP 当优选 IP → 客户端连到一台根本不是 CF 边缘的服务器，握手失败
- 把优选 IP 当 ProxyIP → Worker 绕一圈又回到同一个 Cloudflare，白白多一跳

## 五步判定

每个候选要过五关，比 Worker 端的检测更严格：

| 步骤 | 检查内容 | 不通过说明 |
|---|---|---|
| ① | TCP 能连上 | 端口没开 / 被墙 / DNS 解析失败 |
| ② | 用探测域名做 SNI 能完成 TLS 握手 | 服务器不是反代，或没转发到 CF |
| ③ | **对方返回的证书属于这个探测域名** | 普通服务器只会返回自己的证书 |
| ④ | 请求 `/cdn-cgi/trace` 拿到 CF 响应 | 转发链路不通 |
| ⑤ | **出口 IP 不等于本机公网 IP** | 中间没有中转，只是直连到了 CF 边缘 |

### 第 ③ 步为什么关键

真反代会把 ClientHello **透传**给 Cloudflare 边缘，边缘根据 SNI 返回对应域名的证书。

普通服务器只会返回自己的证书。

> 对比：cmliu 的 Worker 版检测只检查握手首字节是不是 `0x16`，**任何 TLS 服务器都能通过**，假阳性很多。CFSTX 做完整的证书主机名校验（自动处理 `*.example.com` 通配符）。

### 第 ⑤ 步为什么必须

前四步只能证明「对方能到达 Cloudflare 边缘」，证明不了「中间有中转」。

**实测：两类地址全部能通过前四步**：

| 地址 | 前四步 | 出口 IP | 实际类型 |
|---|---|---|---|
| `141.193.213.21:443` | ✅ 通过 | `27.46.74.6`（本机） | ❌ 直连 CF |
| `104.129.167.255:2053` | ✅ 通过 | `27.46.74.6`（本机） | ❌ 直连 CF |
| `3.0.50.69:443` | ✅ 通过 | `3.0.50.69` | ✅ 真中转 |
| `ProxyIP.CA.CMLiussss.net` | ✅ 通过 | `159.203.18.237` | ✅ 真中转 |

**判据**：`/cdn-cgi/trace` 返回的 `ip=` 是 **Cloudflare 看到的连接来源**：

- 等于你的公网 IP → 中间没有任何中转
- 等于别人 → 确实是第三方在转发

## 四类结果标记

| 标记 | 颜色 | 含义 | 能填 PROXYIP 吗 |
|---|---|---|---|
| **可用** | 绿 | 五关全过，是真中转 | ✅ **可以** |
| **直连CF** | 黄 | 出口就是本机，中间没中转 | ❌ **不能**，这是客户端入口 |
| **待验证** | 橙 | 本机解析到 CF 网段，测不了 | ⚠️ 在 Worker 里可能可用 |
| **无效** | 灰 | 连不上 / 证书不对 / 属于 CF 网段 | ❌ |

### 「直连CF」为什么不能填

Worker 会把它当中转站：

```text
Worker ──> 该地址 ──> 又回到同一个 Cloudflare
```

白白多一跳，不解决任何问题。而且 CF 可能把它判定为异常流量。

这类地址属于**客户端入口（优选 IP）**，应该填到订阅的 server 地址里，不是 `PROXYIP`。

**复制按钮会自动排除它们** —— 点「复制为 PROXYIP」只会带上「可用」的。

### 「待验证」是什么情况

有些 ProxyIP 域名是**橙云域名**（如 `proxyip.cmliussss.net`），在本机 DNS 解析出来是 Cloudflare 自己的 IP（`104.x` / `172.x`）。

从你的电脑连它，实际是直连 CF 边缘 —— **测不出真实质量**。

但在 Worker 内部，Cloudflare 的 DNS 会解析到真实源站，所以它**可能能用**。

**建议**：可以配进去实测，但别把它当主力。你不知道它真实状态。

从本机测：
- 有时能通过（显示为直连CF）
- 有时 TLS 超时
- 你无法判断它到底健不健康

### 「无效」的几种原因

| 错误信息 | 含义 |
|---|---|
| `无法连接（端口未开放或被墙）` | TCP 都连不上 |
| `TLS 握手失败（未转发到 Cloudflare 边缘）` | 连上了但不是反代 |
| `证书不属于该域名（是普通服务器，不能作反代）` | 是普通 HTTPS 服务器 |
| `返回 404` / `响应不是 Cloudflare trace` | 转发到了别处 |
| `属于 Cloudflare 自有网段，不能作为 ProxyIP` | 直接给了 CF 的 IP |
| `域名解析超时（DNS 无响应）` | DNS 问题 |
| `域名解析失败（DNS 查询不到该域名）` | 域名不存在或已删 |

点一下就能导入，**可累加**，重复的按 `host:端口` 自动去掉。

| 源 | 更新频率 | 格式 | 典型条数 |
|---|---|---|---|
| **Xgonce** | 每 6 小时 | CSV，带速度/机房/延迟 | ~1200 |
| **Xiaobei09** | 每 3 小时 | `IP:端口#备注` | ~560 |
| **Mingyu** | 每半小时 | 纯 IP，默认 443 | ~10 |
| **cmliussss 地区域名** | 内置 | 18 个分地区域名 | 18 |

### 选哪个

| 情况 | 建议 |
|---|---|
| 想快速出结果 | cmliussss 地区域名（18 条，几秒） |
| 想要最大可用数 | Xgonce + Xiaobei09 一起导 |
| 想要最新的 | Mingyu（半小时更新） |

### 关于 Xgonce 的 CSV

它的表头是：

```text
IP, cf-meta-ip, 端口, 速度(Mbps), CF归属国, 机房, TCP延迟, TLS延迟
```

**两列都是 IP**，而且 227/1202 行的值不一样。

实测 40 组「两列不同」的样本：

| 列 | TCP 通 | TLS 成功 | 证书匹配 |
|---|---|---|---|
| **IP 列** | 30/40 | 30/40 | **30/40** |
| cf-meta-ip 列 | 7/40 | 2/40 | 2/40 |

**IP 列才是真正的 ProxyIP**。`cf-meta-ip` 是元数据地址，不能当反代用。CFSTX 取的是 IP 列。

## v4 / v6 筛选

结果区有两个互斥勾选框：

```text
按出口筛选   □ 只看 v4 出口   □ 只看 v6 出口
```

**按「出口类型」筛选**，不是按入口。

- 出口是 **v6** 的 ProxyIP 只能代理到 IPv6 目标
- 如果目标站点只有 IPv4，会连不上

**大多数场景用 v4。** 除非你确定目标站支持 IPv6。

| **复制地址列表** | 一行一个 `地址:端口` | 网页版检测工具、其他只认纯地址的地方 |

## 填到哪里

### 方式一：环境变量（推荐）

Cloudflare Dashboard → Workers → 你的 Worker → 设置 → 变量和机密 → 添加：

```text
变量名: PROXYIP
值:     3.0.50.69:443,ProxyIP.CA.CMLiussss.net:443
```

保存后重新部署。

### 方式二：admin 面板

edgetunnel 的网页管理界面 → **Cloudflare CDN 访问设置** → 反代模式选 **PROXYIP** → 取消勾选「启动自动获取」→ 粘贴到输入框 → 保存

### 格式说明

edgetunnel 的解析逻辑：

```js
data.replace(/\010/g, ',').replace(/\n/g, ',').split(',')
  .map(s => s.trim()).filter(Boolean)
```

**逗号和换行都会被当成分隔符**，两种写法都能用。

每个地址走 `解析地址端口`：只支持单冒号 `host:port` 和 `[ipv6]:port`。

> [!WARNING]
> **端口别丢**。除了 443，常见还有 8443 / 2053 / 2083 / 2087 / 2096。
> 不写端口默认 443，但如果对方实际用 2053，就连不上。

## 关键认知：多个不是「保险」

edgetunnel 的 `PROXYIP` 是**每次请求随机抽一个**，不是「坏了自动换下一个」：

```js
const proxyIP = proxyIPs[Math.floor(Math.random() * proxyIPs.length)]
```

**所以**：

| 情况 | 实际效果 |
|---|---|
| 3 个都健康 | 各分 1/3，没问题 |
| 3 个里 1 个挂了 | **约 1/3 的请求直接失败**，不会自动降级 |
| 混一个测不了的 | 把整体成功率拉下来 |

**「多个保障」的前提是每个都已经验证健康。**

### 建议的数量

- **3~7 个**：可用性和延迟的平衡点
- 全部经过本机实测「可用」
- 每隔 3~5 天重新测一遍

---

## 稳定性

ProxyIP 都是**第三方服务器**，随时可能：

- 关机
- 换 IP
- 被封
- 限速

**实测波动**：同一批 cmliussss 地区域名，几分钟内两次测试结果可能完全不同（第一轮 CH/NL/CA 全挂，第二轮全通）。

**这不是工具的问题，是节点的问题。**

### 域名比 IP 稳定吗

**部分正确**：

| 场景 | 域名 | 单 IP |
|---|---|---|
| 运营者换了源站 IP | ✅ 改 DNS，你无感 | ❌ 你手里那个直接失效 |
| 服务器机器挂了 | ❌ 一样连不上 | ❌ 一样连不上 |
| DNS 被污染/劫持 | ⚠️ 多一个风险点 | ✅ 不经过 DNS |

**域名解决的是「IP 变了怎么办」，不解决「机器挂了怎么办」。**

### 实际建议

- **域名为主**（抗 IP 变更）+ **留 1~2 个 IP**（快车道、兜底）
- 每隔几天重新测一次
- 测出「无效」就换掉

## 支持的候选写法

```text
1.2.3.4                      → 1.2.3.4:443
1.2.3.4:8443                 → 1.2.3.4:8443
proxyip.example.com          → proxyip.example.com:443
proxyip.example.com:2053     → proxyip.example.com:2053
2606:4700::1                 → [2606:4700::1]:443
[2606:4700::2]:2096          → [2606:4700::2]:2096
https://proxyip.example.com/ → 自动去掉协议和路径
1.2.3.4:443#备注             → # 后面作为备注保留
# 整行注释                    → 跳过
```

## 常见问题

### 检测时提示「取不到本机公网 IP」

说明无法区分「直连 CF」和「真中转」，这次所有结果都不会标「直连CF」。

**常见原因**：正开着代理。程序取本机 IP 时是强制直连的，走代理会失败。

关掉代理再测。

### 为什么同一个地址两次结果不一样

ProxyIP 本身就是波动的。两次之间可能：
- 服务器临时负载高
- 网络线路抖动
- 节点被限速

**多个地址里有一个偶发失败是正常的。**

### 和网页版检测站结果不一致

可能的原因：

| 原因 | 说明 |
|---|---|
| 探测域名不同 | 网页站用固定的，CFSTX 可以用你自己的域名 |
| 检测时机不同 | 节点波动 |
| 检测项不同 | 网页站可能不做证书校验 |
| 粘贴格式 | 网页站只认**纯地址**，带 `PROXYIP=` 前缀会报错 |

**以 CFSTX 的结果为准**，因为它检测更严格，且可选你最真实的探测域名。
