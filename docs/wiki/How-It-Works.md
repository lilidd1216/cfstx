# 原理与限制

理解这些，你才知道工具**能做什么、不能做什么**，以及为什么结果会变。

---

## Cloudflare 的边缘网络

### Anycast：同一个 IP，全球都有

Cloudflare 使用 **Anycast** 技术：同一个 IP 地址在全球数百个机房同时宣告。

```text
           ┌─ 香港机房
你的电脑 ──┼─ 洛杉矶机房
           └─ 新加坡机房
     ↑
  同一个 IP（如 104.16.0.1）
```

理论上，网络会把你的流量路由到**最近**的机房。

### 但「最近」不等于「最快」

实际路由由 BGP 决定，受这些因素影响：

| 因素 | 影响 |
|---|---|
| 国际出口拥塞 | 晚高峰时电信/联通出口经常堵 |
| 运营商互联质量 | 不同运营商到同一机房的路由不同 |
| Cloudflare 机房负载 | 单机房的服务器负载不均 |
| QoS / 限速 | 部分 IP 段被针对性限速 |
| 路由绕行 | 物理上近，但路由绕了一大圈 |

**这就是为什么需要「优选 IP」** —— 同样在 Cloudflare 网段内，不同 IP 到你的实际路径可能完全不同。

### 为什么不同 IP 的延迟差这么多

一个 IP 被路由到香港机房，延迟可能 50ms；另一个被路由到洛杉矶，可能 200ms。

**你无法通过 IP 本身判断它会走哪个机房** —— 只能实测。

## 测速原理

CFSTX 提供三种测量方式，测的是不同层面的东西。

### TCPing（默认）

```text
你的电脑 ──SYN──> 目标 IP
         <─SYN+ACK─
         ──ACK──>
```

测的是 **TCP 三次握手的往返时间（RTT）**。

| 优点 | 缺点 |
|---|---|
| 快 | 只证明 TCP 层通，不证明能建站 |
| 不消耗 Cloudflare 配额 | 拿不到机房信息 |
| 不受 HTTP 层影响 | TLS 握手、HTTP 处理的开销没算进去 |

**适用**：只是挑 IP 填客户端。

### HTTPing

```text
你的电脑 ──TCP 握手──> 目标
         ──TLS 握手──>
         ──HTTP 请求──>
         <─HTTP 响应──
```

测的是**完整的一次 HTTP 请求**。

| 优点 | 缺点 |
|---|---|
| 更接近真实使用 | 慢 |
| 能拿到 `colo`（机房代码） | 受 Cloudflare 配额影响 |
| 能验证 HTTP 状态码 | 每个 IP 都要发请求 |

**适用**：想按机房筛、想验证站点真的能打开。

### 下载测速

对延迟最低的 N 个 IP，实际下载一个文件，测吞吐。

| 优点 | 缺点 |
|---|---|
| 反映真实带宽 | 很慢（默认每个 10 秒） |
| 能发现「延迟低但速度差」的 IP | 消耗较多流量 |

**适用**：对速度有要求时。

## 为什么结果会波动

**这是正常现象，不是 bug。**

### 原因

| 原因 | 说明 |
|---|---|
| **Anycast 路由变化** | BGP 路由随时可能调整，同一个 IP 可能换机房 |
| **网络拥塞** | 晚高峰国际出口拥堵，延迟上升 |
| **Cloudflare 负载均衡** | 机房内部的服务器分配会变 |
| **随机抽样** | 每个 /24 段随机取一个 IP，每次抽到的不同 |
| **IP 本身的变化** | 部分 IP 可能临时下线或新增 |

### 典型表现

```text
第一次测：3.0.50.69  106ms
第二次测：3.0.50.69  180ms
```

同一个 IP，不同时间结果不同 —— 不是工具的问题。

**实测案例**：一批社区 ProxyIP 域名，几分钟内两次测试结果可能完全反转（第一轮 CH/NL/CA 全挂，第二轮全通）。

### 怎么办

- **接受波动**，不要追求「完美的结果」
- **每隔几天重测一次**
- **多留几个备选**，不要只依赖一个 IP

## 为什么测速结果 ≠ 实际使用体验

测速测的是**单一维度**，实际使用受更多因素影响。

### 测速没覆盖的

| 因素 | 说明 |
|---|---|
| **你的域名路由** | 通用测速地址能连，不代表你的 Worker 域名能连（→ 域名探测） |
| **目标网站的位置** | 访问美国站和日本站的体验不同 |
| **协议开销** | TLS、WebSocket、代理协议本身有开销 |
| **客户端实现** | 不同客户端的分流规则、重试策略不同 |
| **长期稳定性** | 测速是瞬时值，不代表几小时后还这么好 |
| **被 QoS 的表现** | 测速时可能不触发限速，持续大流量时才触发 |

### 这就是为什么

- 需要**自定义测速域名**（验证你域名的路由）
- 需要 **ProxyIP 检测**（验证 Worker 回源链路）
- 需要**定期重测**（应对波动）

## 域名探测的原理

### 问题

Cloudflare 的边缘 IP 并不是都配置了所有域名的路由。

```text
IP A ──> 有 fast3.example.com 的路由  ✅
IP B ──> 没有，返回 403 (error 1034)  ❌
```

通用测速地址（`speed.cloudflare.com`）在所有 IP 上都有路由，所以**测不出这个差异**。

### 解决

用**你自己的域名**请求一个特殊路径：

```text
https://fast3.example.com/cdn-cgi/trace
```

- 返回 `200` 且含 `colo=` → 这个 IP 配置了你域名的路由
- 返回 `403` / 超时 → 没有

### 为什么不消耗 Workers 配额

`/cdn-cgi/trace` 由 **Cloudflare 边缘节点直接生成响应**，请求**根本不会进入 Worker 脚本**。

所以不计入 Workers 每日请求数，可以放心对几千个地址做探测。

### 实测效果

某个 Worker 域名的 5955 个候选 IP 中，只有约 **1500 个（25%）** 真正服务它。

**换句话说：不做域名探测，你筛出来的 IP 有 75% 概率是用不了的。**

## ProxyIP 的原理

### Workers 的 connect() 限制

Cloudflare Workers 提供了 `connect()` API 用于发起 TCP 连接，但有硬性限制：

> **禁止连接 Cloudflare 自己的 IP 段。**

### 为什么需要 ProxyIP

当一个 Worker 需要回源到某个也在 Cloudflare 上的目标时，`connect()` 会失败。

ProxyIP 是一台**第三方服务器**，夹在中间：

```text
Worker ──connect()──> ProxyIP（第三方，不在 CF 网段）
                          │
                          └──转发──> Cloudflare 边缘 ──> 目标站
```

### 为什么检测要五步

| 步骤 | 排除的假阳性 |
|---|---|
| ① TCP 通 | 端口没开 / 被墙 |
| ② TLS 握手 | 不是 TLS 服务 |
| ③ 证书校验 | 普通 HTTPS 服务器（返回自己的证书） |
| ④ trace 200 | 转发到了别处 |
| ⑤ 出口 ≠ 本机 | **直连 CF 的入口 IP** |

**第 ③ 步**：真反代会把 ClientHello 透传给 Cloudflare，CF 根据 SNI 返回对应域名的证书。普通服务器只返回自己的。

**第 ⑤ 步**：前四步只能证明「能到达 CF」，证明不了「有中转」。出口 IP 等于你自己，说明根本没有中转。

## 工具的边界

### 能做的

- ✅ 从大量候选里筛出当前网络下可用的
- ✅ 按你的条件（延迟/速度/丢包/机房）过滤
- ✅ 验证 IP 是否服务你的域名
- ✅ 验证 ProxyIP 是否真的在转发
- ✅ 把结果格式化成客户端能直接用的形式

### 不能做的

| 做不到 | 原因 |
|---|---|
| ❌ 保证结果长期有效 | 网络随时变化 |
| ❌ 测出「被 QoS 后」的真实表现 | 测速是短时行为 |
| ❌ 替代实际使用测试 | 测速是单一维度 |
| ❌ 加速所有 Cloudflare 站点 | hosts 只对指定域名生效 |
| ❌ 绕过 Cloudflare 的服务条款 | CF 禁止代理套 CDN |

### 关于「测出来的最优」

**「最优」是相对于「当前时刻、当前网络、当前候选集」的。**

- 换个时间测，结果会变
- 换个网络测，结果会变
- 候选集不同，结果会变

**它不是绝对最优，是当前条件下的相对最优。**

---

## 使用建议

| 建议 | 原因 |
|---|---|
| 关代理再测 | 否则测的是代理出口的质量 |
| 用自定义测速域名 | 否则 75% 的 IP 可能对你的域名无效 |
| 每隔几天重测 | 应对节点波动 |
| 多留几个备选 | 单个 IP 失效时还有别的 |
| 不要指望一次测完永久有效 | 网络是动态的 |
| 优先信自己的实测，不迷信「公共优质列表」 | 别人的网络和你的不一样 |
