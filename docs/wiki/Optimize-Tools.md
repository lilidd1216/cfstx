# 优化工具

左侧导航第三项。把测速结果延伸到实际使用场景。

页面包含两块：**Hosts 加速** 和 **客户端订阅优化**。

---

## Hosts 加速

### 它解决的问题

**浏览器直连你的域名时，走的是 DNS 解析出的 IP，和你优选出来的 IP 无关。**

这是「优选了一堆 IP，打开自己的网站还是很慢」的最常见原因：

```text
浏览器输入 fast3.example.com
  → 系统 DNS 解析
  → 返回一个随机分配的 Cloudflare IP（可能很远）
  → 走那个 IP，不会用你测出来的最快节点
```

把域名写进 hosts 后，直连也会走你筛过的节点：

```text
浏览器输入 fast3.example.com
  → 系统先查 hosts → 命中你写的 IP
  → 走你选的最快节点
```

### 什么时候用

| 场景 | 需要吗 |
|---|---|
| 浏览器里直接访问自己的 Worker / Pages 域名 | ✅ **需要** |
| 只通过客户端订阅访问 | ❌ 不需要，客户端已经用了优选 IP |
| 想加速所有 Cloudflare 站点 | ❌ hosts 做不到，见本文末尾的「配套脚本」 |

### 操作步骤

**前提**：需要管理员权限。

1. **关闭 CFSTX**
2. 找到 `cfstx.exe`，**右键 →「以管理员身份运行」**
3. 左侧点「**优化工具**」
4. 选择 IP：
   - 从列表里点选（只列出 **443 端口**的测速结果）
   - 或在输入框手填
5. 填域名（支持多个）
6. 点「**应用到 Hosts**」

成功后提示：

```text
已写入 hosts：104.16.0.1 → fast3.example.com（DNS 缓存已刷新）
```

7. 浏览器 `Ctrl + F5` 强制刷新

### 多个域名

域名输入框支持多行，也支持一行内用逗号/分号/空格分隔：

```text
fast3.example.com
www.example.com
api.example.com
```

或者：

```text
fast3.example.com, www.example.com, api.example.com
```

失焦后会自动清理成一行一个。

**所有域名都指向同一个 IP。**

### 端口限制（重要）

**hosts 文件只做「域名 → IP」的映射，没有端口这个概念。**

格式就是：

```text
IP 域名
```

浏览器访问 `https://fast3.example.com` 时，系统先查 hosts 得到 IP，然后**固定连接 443 端口**。

所以：

| 输入 | 能否用于 hosts |
|---|---|
| `52.74.51.158:443` | ✅ 可以（端口自动去掉，正好对上） |
| `104.16.0.1`（无端口，默认 443） | ✅ 可以 |
| `27.44.142.135:10001` | ❌ **不行**，这个 IP 的 443 端口没开 |

**为什么会拒绝非 443 端口**：

如果强行写 `27.44.142.135`，浏览器会去连 `27.44.142.135:443`，那个端口没开，网页直接打不开。

程序会明确提示：

```text
10001 端口不能用：hosts 只做域名解析，浏览器访问 https 固定走 443，写进去会连不上
```

### 通配符（不支持）

**hosts 不支持 `*.example.com`。**

系统只做精确字符串匹配，`*.lds1216.ccwu.cc` 这种写法写进去**完全无效**。

要覆盖多个子域名，只能一行一个写全：

```text
52.74.51.158 fast3.example.com
52.74.51.158 www.example.com
52.74.51.158 api.example.com
```

填了通配符会立刻标红，且「应用到 Hosts」按钮保持禁用。

### 备份与还原

- 每次修改前，自动备份原 hosts 到：

```text
%APPDATA%\CFSTX\hosts-backup\
```

- CFSTX **只维护标记块之间的内容**：

```text
# === CFSTX BEGIN ===
104.16.0.1 fast3.example.com
# === CFSTX END ===
```

**原有内容一行不动。**

- 点「**移除**」随时清空标记块内的内容，同样会刷新 DNS 缓存

### DNS 缓存

写完 hosts 后，**程序会自动执行 `ipconfig /flushdns`**。

**为什么需要**：hosts 的优先级高于 DNS，写入后立即生效。但 Windows 的 DNS Client 服务仍缓存着之前的解析结果，不清理的话浏览器可能还连着旧 IP。

### 生效验证

打开命令提示符：

```bat
ping 你的域名
```

返回的 IP 应该就是你刚写入的那个。

如果还是旧 IP：

| 检查项 | 操作 |
|---|---|
| 是否以管理员身份运行 | 重新右键 →「以管理员身份运行」 |
| 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 浏览器 keep-alive | 关掉浏览器重新打开 |
| 插件干扰 | 无痕窗口试试 |
| 系统缓存 | 手动执行 `ipconfig /flushdns` |

**不需要**：重启电脑、禁用/启用网卡、重启路由器。

### IP 失效了怎么办

hosts 里的 IP 失效后，该域名会**打不开**（不是回退到 DNS）。

**解决**：重新测速 → 重新应用一次。或者先点「移除」恢复正常的 DNS 解析。

## 客户端订阅优化

针对「订阅更新经常失败」，页面内给出三步处理。

### 1. DIRECT 规则

**问题**：更新订阅时走了代理，而当前节点已经失效 —— 形成死循环：

```text
更新订阅 → 走代理 → 节点已失效 → 订阅更新失败
```

**解决**：给订阅域名加 DIRECT 规则，让它**直连**更新，不走代理。

页面会根据你填的域名自动生成规则片段，可一键复制：

```yaml
rules:
  - DOMAIN-SUFFIX,fast3.example.com,DIRECT
```

粘到客户端的规则配置里即可。

### 2. 超时调整

**现象**：订阅偶尔更新失败，重试又好了。

**原因**：国内到 Cloudflare 偶尔因丢包触发 TCP 重传（1s → 2s → 4s → 8s），单次请求可能超过 15 秒。

**解决**：把订阅请求的超时时间调到 **60 秒**。

各客户端的设置位置不同，一般在「订阅设置」或「高级设置」里。

### 3. 排查清单

订阅仍然失败时，按顺序检查：

| 检查项 | 说明 |
|---|---|
| 订阅链接是否有效 | 浏览器直接打开看看能不能返回内容 |
| 是否走了代理 | 加 DIRECT 规则后再试 |
| 超时是否够长 | 调到 60 秒 |
| 域名是否被墙 | 换个网络环境试试 |
| 客户端版本 | 旧版客户端可能不支持某些订阅格式 |
| 订阅内容是否为空 | 服务端问题 |

## 配套脚本

`script/` 目录提供 Windows 批处理脚本，用于把测速结果自动应用到系统配置：

| 脚本 | 用途 |
|---|---|
| `cfstx_hosts.bat` | 自动更新 Hosts 中的 Cloudflare CDN IP |
| `cfstx_3proxy.bat` | 更新 3Proxy 配置，一次性加速所有 Cloudflare 站点 |
| `cfstx_ddns.bat` | 通过 Cloudflare API 自动更新域名解析 |

> 这些脚本来自上游项目，适合有命令行基础的用户。

## 进阶：多账号与节点池

> 当单个 Cloudflare 账号的 **10 万请求/天**不够用时。
>
> **先确认你缺不缺**：Cloudflare 后台 → Workers 和 Pages → 看「请求」曲线。日请求不到 5 万就别折腾，多账号的维护成本远高于收益。

---

### ① 三条路：先选方向

| 方案 | 额度 | 成本 | 复杂度 | 风险 |
|---|---|---|---|---|
| **付费 Workers** | 1000 万/天 | $5/月 | 后台点一下 | 无 |
| **多账号多节点** | 10 万 × N | 免费 | 每个账号部署一次 | 账号关联、ToS |
| **Snippets 绕过** | 不按 Worker 计费 | 免费 | 中 | 功能受限，不能用 `connect()` |

**怎么选**：

- 能接受每月 $5 → **直接付费**，1000 万请求是免费的 100 倍，最省心
- 完全不想付费、且有多个现成账号 → 多账号
- 只想跑纯 HTTP 转发、不需要 `connect()` → Snippets

> 为了省 $5 去注册并维护 N 个账号，要承担 N 份封号风险，通常不划算。多账号适合「就是不想付钱」的人，不适合「想省事」的人。

---

### ② 多账号多节点：具体怎么配

> **前提**：必须是**真正不同的 Cloudflare 账号**。
> 同一个账号下开 3 个 Worker，额度是**共享**的，不会变成 30 万。

#### 步骤 1：面板账号，记下 UUID

打开已有的 EdgeTunnel 2.0 面板 → **⚙️ 详细配置信息** → 复制 `UUID`。这一串是所有节点共用的身份标识。

#### 步骤 2：第二账号，部署节点

换一个 Cloudflare 账号，用同一份 `edgetunnel-main.zip` 部署 Pages。

**不要设 `ADMIN`，不要绑 KV** —— 它只当节点，不需要管理面板。

#### 步骤 3：给节点设 UUID

第二账号的项目 → 设置 → 变量 → 添加：

```text
变量名  UUID
变量值  8fc6a982-9862-4362-846f-a7039c5e2e47   ← 换成你自己的
```

然后**重新部署一次**让变量生效。

#### 步骤 4：给节点绑域名

第二账号的项目 → 自定义域 → 绑一个**和面板不同的**子域名：

```text
面板     edt2.example.com
节点 2   edt2-2.example.com
节点 3   edt2-3.example.com
```

绑完等 10~30 分钟验证通过。

#### 步骤 5：面板把节点域名加进 HOSTS

回到面板 → **⚙️ 详细配置信息** → `HOSTS`，把节点 2、节点 3 的域名都加进去：

```text
HOSTS:
edt2.example.com
edt2-2.example.com
edt2-3.example.com
```

保存。

#### 步骤 6：重新拉订阅验证

客户端删掉旧订阅重新导入。节点列表里应该出现不同域名的节点，**顺序每次刷新都不一样**。

顺序会变是正常的 —— 面板每次生成订阅都会把 `HOSTS` 打乱，让流量自然分散到不同账号。

#### 它为什么能降低 SNI 阻断

面板在替换订阅里的域名时，会把域名中的 `*` 换成 3~16 位随机字符：

```text
*.example.com  →  a3k9x2f.example.com
```

每次订阅拿到的子域都不同，批量检测很难建立稳定的黑名单。

这条**与账号数量无关，单个账号也能用**。

#### 三个必须注意的

- **账号之间不能有关联特征**：同一邮箱后缀、同一张卡、同一 IP 批量注册，会被风控串起来一起封
- **不要公开分享节点**：一旦被滥用，轻则限速重则封号
- **某个账号挂了只影响它自己的节点**：这正是多账号的价值——故障被隔离了

### ③ 开源项目：别人是怎么做的

这几个项目都在解决同一个问题——**把请求分散到多个 Worker / 多个账号**。按需选用，不必全上。

#### FlareTunnel

**语言**：Go　·　**特点**：多账号管理

自动部署多个 Worker 作为代理端点，支持随机 / 轮询负载均衡。最有价值的是**按账号的配额统计**——能看出哪个账号快用完了。还带黑名单过滤。

- **适合**：想统一管理多个账号，需要知道每个账号的剩余额度
- **地址**：https://github.com/MorDavid/FlareTunnel

#### flaregun

**语言**：npm　·　**特点**：一行命令部署

`flaregun up 5` 直接部署 5 个 Worker。

三种轮换策略：round-robin、random、**adaptive**（遇到 429 / 5xx 自动指数退避）。所有命令支持 `--json`，方便脚本化。

- **适合**：想要最少手工步骤，快速拉起一批
- **地址**：https://www.npmjs.com/package/@miclivs/flaregun

#### ech-snippets

**语言**：JS　·　**特点**：绕过额度

思路和别人不一样：把代码改成用 **Cloudflare Snippets** 部署。Snippets **不按 Worker 请求计费**，因此完全绕开每天 10 万的限制。

- **适合**：纯 HTTP 转发场景
- **注意**：Snippets 不能使用 `connect()`，只能做 HTTP 层转发
- **地址**：https://github.com/Neomanbeta/ech-snippets

#### cf-relay

**语言**：npm　·　**特点**：极简中继

一键部署的边缘中继 Worker，通过 `x-relay-target` / `x-relay-path` 请求头转发。官方建议「在多个 Cloudflare 账号部署同一 Worker」来获得更多出口 IP 和配额。

- **适合**：只要一个最简单的转发层
- **地址**：https://www.npmjs.com/package/cf-relay

> **和 EdgeTunnel 2.0 自带方案的关系**
>
> EdgeTunnel 2.0 的「单面板多节点」已经覆盖了大部分需求，上面这些项目是替代或补充：
> - 想要配额统计 → FlareTunnel
> - 想要最少手工 → flaregun
> - 想彻底绕开 Worker 计费 → ech-snippets
> - 只要转发，不要面板 → cf-relay

### ④ 和 CFSTX 配合：优选 IP 怎么喂进去

多节点部署好之后，每个**域名**都需要各自的优选 IP —— 不同域名的边缘路由不一样，同一批 IP 不一定都服务它们。

#### 步骤 1：打开自定义测速域名

在「优选IP」页填你要用的那个节点域名，测出只服务它的 IP。

**有几个节点域名就测几次**，各测各的。

#### 步骤 2：导出 TXT

CFSTX 导出的格式是 `IP:端口#地区 速度`，和 EdgeTunnel 2.0 的「自定义优选」格式**天然兼容**：

```text
27.44.142.135:10001#HKG 40.66MB/s
120.240.179.158:10001#HKG 25.22MB/s
104.234.174.220:443#SIN 12.06MB/s
```

#### 步骤 3：粘进 EdgeTunnel 2.0

面板 → 自定义优选 → 手动添加 → 粘贴 → 保存。

需要 EdgeTunnel 自动定时拉取的，可以用「优选 API」，填一个返回同样格式的 URL。

> **当前限制**：CFSTX 一次只能探测**一个**域名。有多个节点域名时，只能一个个测、分别导出。多域名探测在计划中，还没做。
