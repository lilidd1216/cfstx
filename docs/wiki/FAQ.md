# 常见问题

按症状查。每个问题按「现象 → 原因 → 解决」组织。

---

## 安装与运行

### 安装时提示「无法验证发布者」

**现象**：双击安装包，Windows 弹出「Windows 已保护你的电脑」或 SmartScreen 蓝屏。

**原因**：程序未购买代码签名证书。所有未签名的 exe 都会触发这个提示，**不是病毒警告**。

**解决**：

1. 点击「**更多信息**」
2. 点击「**仍要运行**」

### 双击后没有反应 / 闪一下就没了

**检查 1**：是否缺少 WebView2 运行时？

程序界面依赖 WebView2。Windows 11 自带；Windows 10 可能没有。

安装微软官方组件：https://developer.microsoft.com/microsoft-edge/webview2/

**检查 2**：是否被杀毒软件拦截？

部分杀软对未签名程序比较敏感，加白名单即可。

**检查 3**：尝试用命令行启动看报错

```bat
cd /d "安装目录"
cfstx.exe -v
```

如果可以输出，说明程序本身正常，问题在界面层（WebView2）。

### 装在哪个目录

默认：

```text
%LOCALAPPDATA%\Programs\CFSTX\
```

用户目录，**不需要管理员权限**。

### 怎么卸载

Windows 设置 → 应用 → 找到 CFSTX → 卸载。

或者直接运行安装目录下的 `unins000.exe`。

## 测速相关

### 测速结果很好，但客户端里大量 timeout

**这是最常见的问题。**

**现象**：CFSTX 显示一堆可用 IP，延迟很低，填进客户端后大量节点连不上，或者能连但打不开网页。

**原因**：

CFSTX 默认用 `speed.cloudflare.com` 测速，验证的是「这个 IP 能否连上 Cloudflare」。

但你的客户端访问的是**自己的** Worker / Pages 域名。

**两者的路由并不完全重合** —— Cloudflare 的部分 Anycast IP 没有配置你域名的边缘路由，访问会返回 `403`（`error code: 1034`）或直接超时。

**解决**：

1. 打开「延迟测速」卡片里的「**自定义测速域名**」
2. 填入**你实际访问的域名**，如 `fast3.example.com`
3. 重新测速

程序会先用 `<域名>/cdn-cgi/trace` 探测，只保留真正服务该域名的 IP。

**实测效果**：某个 Worker 域名的 5955 个候选 IP 中，只有约 1500 个（25%）真正服务它。

详细说明：→ [优选IP → 自定义测速域名](Speed-Test#自定义测速域名)

### 可用 IP 很多，但下载速度全是 0.00

**这通常不是故障。**

**原因**：

1. **只测了前 N 个**：默认只对延迟最低的 10 个做下载测速，其余 IP 的速度显示为 0
2. **测速还在进行中**：下载测速是单线程排队执行，表格里未轮到的显示 0
3. **确实没达到速度下限**：所有 IP 都没达到「速度下限」时，程序会返回全部结果并提示

**解决**：

- 想测更多 → 调大「测速数量」
- 想看具体原因 → 勾「调试模式」重测

### 延迟异常低（比如 0.xx ms）

**原因**：测速走了代理。代理出口可能就在 Cloudflare 附近，导致延迟看起来极低。

**解决**：关闭 VPN / 代理软件后重新测速。

程序在开始测速时会自动检测系统代理并提醒。

### 一个 IP 都筛不出来

**先看诊断弹窗**：程序会按五步流程展示卡在哪一步，红色高亮。

| 卡在 | 说明 | 调整 |
|---|---|---|
| ① 加载到的测速目标 | `ip.txt` 没找到 | 确认文件与 exe 同目录 |
| ② 延迟测速连通 | 网络不通 / 开着 VPN | 关代理、检查网络 |
| ③ 通过延迟、丢包过滤 | 延迟上限太严 | 改成 9999 看分布 |
| ④ 完成下载测速 | 测速地址被限流 | 等一段时间或换地址 |
| ⑤ 最高下载速度 | 下载全部失败 | 检查 `-debug` 日志 |

**中国大陆到 Cloudflare 的延迟经常在 150~250ms**（走美西）。如果延迟上限设 150，很可能一个都没有。

### 测速返回 429 / 全部 IP 不可用

**原因**：Cloudflare 的 `__down` 端点有配额限制。

程序已让延迟测速使用 `bytes=0` 规避，但**下载测速**密集执行仍可能触发。

**解决**：

- 等一段时间（或次日 UTC 00:00 后）再试
- 或改用自建测速地址（`-url` 参数 / 界面「测速地址」）

### 测速结果每次都不一样

**正常。**

每次都是在每个 IP 段中随机抽取 IP，且网络状况本身在变化。

### 点击开始测速立刻结束、结果为 0

**原因**：`ip.txt` 没找到。

**解决**：确认 `ip.txt` 与 `cfstx.exe` 在同一目录。

程序按「当前工作目录 → exe 所在目录」顺序查找。

### 开始测速时提示「检测到系统代理已开启」

**原因**：Windows 系统代理处于开启状态。

此时测速流量会经过代理，得到的延迟和速度反映的是**你的电脑到代理出口**的情况，不是本地网络直连 Cloudflare 的质量。

**选择**：

- 要筛选**直连可用**的 IP → 关闭代理后重测
- 只想知道代理出口的质量 → 选「仍然开始」

### 下载速度全部为 0，想看具体原因

勾选「调试模式」重测，或命令行加 `-debug`。

看日志里的报错：

| 报错 | 含义 |
|---|---|
| `connection reset by peer` | 链接被重置，测速地址或 IP 被阻断 |
| `HTTP 状态码: 403` | 测速地址拒绝访问（多半是 bytes 超限） |
| `HTTP 状态码: 429` | 触发配额限制 |
| `context deadline exceeded` | 请求超时 |
| `tls: handshake failure` | 测速地址与测速 IP 不匹配 |
| `certificate is valid for XXX, not YYY` | 证书不包含该域名 |

## ProxyIP 相关

### 显示「直连CF」，能用吗

**不能。**

「直连CF」表示 `/cdn-cgi/trace` 返回的出口 IP **就是你自己**，中间没有任何中转。

填进 `PROXYIP` 会让 Worker：

```text
Worker → 该地址 → 又回到同一个 Cloudflare
```

白白多一跳，不解决任何问题。

**这类地址是客户端入口（优选 IP）**，应该填到订阅的 server 地址里，不是 `PROXYIP`。

**复制按钮会自动排除它们。**

详细说明：→ [ProxyIP → 四种结果标记](ProxyIP#四类结果标记)

### 显示「待验证」，能用吗

**可能能用，但本机验证不了。**

这些域名是**橙云域名**（如 `proxyip.cmliussss.net`），在你的电脑上解析出来是 Cloudflare 自己的 IP。

从本机连它，实际是直连 CF 边缘 —— 测不出真实质量。

但在 Worker 内部，Cloudflare 的 DNS 会解析到真实源站，所以它**可能能用**。

**建议**：可以配进去实测，但别当主力。你不知道它真实状态。

### 为什么同一个地址两次结果不一样

**ProxyIP 本身就是波动的。**

两次之间可能：

- 服务器临时负载高
- 网络线路抖动
- 节点被限速
- 被墙

**多个地址里有一个偶发失败是正常的。**

### 检测时提示「取不到本机公网 IP」

**原因**：程序取本机公网 IP 时是**强制直连**的（不走系统代理）。如果开着代理，或网络封锁了 Cloudflare，就取不到。

**后果**：这次无法区分「直连 CF」和「真中转」，所有结果都不会标「直连CF」。

**解决**：关掉代理再测。

### 我填了多个 ProxyIP，为什么还是经常失败

**关键认知**：edgetunnel 的 `PROXYIP` 是**每次请求随机抽一个**，不是「坏了自动换下一个」。

```js
const proxyIP = proxyIPs[Math.floor(Math.random() * proxyIPs.length)]
```

**所以**：

- 3 个都健康 → 各分 1/3，没问题
- 3 个里 1 个挂了 → **约 1/3 的请求直接失败**
- 混一个测不了的 → 把整体成功率拉下来

**「多个保障」的前提是每个都已经验证健康。**

**建议**：

- 只填标「可用」的
- 3~7 个为宜
- 每隔 3~5 天重新测一遍

### ProxyIP 该填到哪里

**edgetunnel 有两个位置**：

| 方式 | 位置 |
|---|---|
| **环境变量**（推荐） | Workers → 设置 → 变量和机密 → `PROXYIP` |
| **admin 面板** | Cloudflare CDN 访问设置 → 反代模式选 PROXYIP → 粘贴 → 保存 |

格式：逗号或换行分隔：

```text
3.0.50.69:443,ProxyIP.CA.CMLiussss.net:443
```

**端口别丢**。除了 443，常见还有 8443 / 2053 / 2083 / 2087 / 2096。

### 和网页版检测站结果不一致

**可能的原因**：

| 原因 | 说明 |
|---|---|
| 探测域名不同 | 网页站用固定的，CFSTX 可以用你自己的域名 |
| 检测时机不同 | 节点波动 |
| 检测项不同 | 网页站可能不做证书校验 |
| 粘贴格式 | 网页站只认**纯地址**，带 `PROXYIP=` 前缀会报错 |

**以 CFSTX 的结果为准**，因为它检测更严格，且可选你最真实的探测域名。

## Hosts 相关

### Hosts 写入失败

**检查 1**：是否以管理员身份运行？

hosts 文件在 `C:\Windows\System32\drivers\etc\hosts`，普通权限无法写入。

关闭程序 → 右键 exe →「以管理员身份运行」。

**检查 2**：是否被安全软件拦截？

部分杀软会保护 hosts 文件。

**检查 3**：提示了具体错误？

程序会给出明确的错误信息，按提示处理。

### 提示「端口不能用」

**原因**：hosts 只做「域名 → IP」映射，**不支持端口**。

浏览器访问 https 固定走 443。

**解决**：只能用 443 端口的结果。带其他端口的 IP（如 `:10001`）不能用于 hosts。

### 填了通配符被拒绝

**原因**：hosts 不支持 `*.example.com`。系统只做精确字符串匹配。

**解决**：把要用到的子域名逐个写全，用换行或逗号分隔：

```text
fast3.example.com
www.example.com
api.example.com
```

### 写入了但没生效

**按顺序检查**：

| 检查项 | 操作 |
|---|---|
| 程序是否以管理员运行 | 重新右键 →「以管理员身份运行」 |
| 浏览器缓存 | `Ctrl + F5` 强制刷新 |
| 浏览器 keep-alive | 关掉浏览器重新打开 |
| 插件干扰 | 无痕窗口试试 |
| 系统 DNS 缓存 | `ipconfig /flushdns` |

**不需要**：重启电脑、禁用/启用网卡、重启路由器。

**验证方法**：

```bat
ping 你的域名
```

返回的 IP 应该就是你写入的那个。

### 应用后网站打不开了

**原因**：写入的 IP 失效了。

hosts 不会回退到 DNS，IP 失效就是打不开。

**解决**：

- 重新测速 → 重新应用一次
- 或点「移除」恢复正常的 DNS 解析

### 原 hosts 内容会丢吗

**不会。**

程序只维护标记块之间的内容：

```text
# === CFSTX BEGIN ===
104.16.0.1 fast3.example.com
# === CFSTX END ===
```

**原有内容一行不动**，且每次修改前会自动备份到：

```text
%APPDATA%\CFSTX\hosts-backup\
```

## 应用内更新

### 检测不到新版本

**检查**：

- 网络是否能访问 Gitee
- 是否用的是免安装版（免安装版**没有**应用内更新）

### 更新下载失败

**可能原因**：网络中断、磁盘空间不足、Gitee 临时不可用。

**解决**：到 [Releases](https://gitee.com/liliaic/cfstx/releases) 手动下载安装包。

### 免安装版怎么更新

**手动**：下载新的 zip，解压覆盖即可（配置文件在 `%APPDATA%\CFSTX\`，不会被覆盖）。

## 其他

### 我的配置保存在哪

```text
%APPDATA%\CFSTX\
```

包括：测速配置、Hosts 备份、日志。

卸载程序不会删除这个目录。

### 怎么导出日志

结果为零时弹出的诊断窗里，有「导出运行日志」按钮。

日志包含：版本、系统、配置目录、配置摘要、各阶段统计与失败原因。

反馈问题时附上这个文件。

### 支持 Linux / macOS 吗

**不支持。**

本项目在原版基础上移除了 Linux / macOS 支持，专注 Windows 桌面体验（WebView2 界面）。

需要跨平台请使用上游项目：https://github.com/XIU2/CloudflareSpeedTest

## 还没解决？

1. 先看 [原理与限制](How-It-Works)，理解工具能做什么、不能做什么

3. 提新 Issue 时附上：**版本号、系统版本、诊断日志、复现步骤**
